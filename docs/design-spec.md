# 际联 SaaS 页面与视觉设计规范

可编辑版本：[Figma 页面 Mock](https://www.figma.com/design/4i3aFEZX5kfSf4Ty19kbFE)

## 1. 设计方向

参考 Geeky Next.js 的内容型结构，但不复制其品牌：

- 顶部白底导航、圆角胶囊激活态；
- 大字号黑色标题配单一品牌强调色；
- Hero 左文案、右人物/服务视觉；
- 大面积白色与浅灰波形/层次背景；
- 卡片用图片、标签、标题、摘要建立内容层级；
- 将博客的“Featured/Recent”结构转换为“精选案例/留学指南”；
- 保留高可读性，不使用模板化渐变和过多玻璃效果。

## 2. 视觉系统

### 2.1 色彩

| Token | 色值 | 用途 |
|---|---|---|
| Brand Teal | `#21A889` | 主按钮、激活态、链接 |
| Brand Deep | `#083D4A` | 品牌深色、关键数据 |
| Ink | `#111827` | 标题、正文主色 |
| Muted | `#667085` | 辅助文字 |
| Canvas | `#FFFFFF` | 主背景 |
| Surface | `#F5F7F8` | 分区背景、卡片底 |
| Border | `#E5E7EB` | 分割线和输入框 |
| Warning | `#B54708` | 待处理/提醒 |

### 2.2 字体

- 中文：Noto Sans SC / 思源黑体；
- 英文与数字：Manrope；
- H1：64/72，700；移动端 40/48；
- H2：40/48，700；移动端 30/38；
- 正文：16/28；
- 标签：13/20，600。

### 2.3 布局

- 桌面画板 1440px，内容最大宽 1200px；
- 12 栏栅格，24px gutter；
- Section 上下间距 96px；移动端 64px；
- 卡片圆角 16px，按钮使用胶囊圆角；
- 关键页面必须同时设计 1440px 和 390px。

### 2.4 标志性元素

“路线卡 Route Card”：把国家、申请季、任务进度表示为一条可延伸的路径节点。它既是品牌视觉，也是真实服务状态组件；避免无意义装饰。

## 3. Mock 范围

Figma 第一版包含以下桌面核心屏：

1. 官网首页；
2. 留学服务/内容列表；
3. 导师列表与导师详情；
4. 学生案例列表与详情；
5. 三步预约页；
6. 学生 Portal 总览；
7. Case 服务计划；
8. 导师预约与学生工作台；
9. 管理员 Lead/Case 列表。

## 4. 页面结构

### 4.1 官网首页

```text

│ 大标题与价值主张              人物/路线视觉          │
│ [免费评估] [了解服务]         服务标签与可信数据      │
├ 精选服务：留学申请 / 学签 / 旅游签 ────────────────┤

├ 服务流程 Route Card ──────────────────────────────┤

├ 最新指南（内容卡片，参考 Recent Posts） ───────────┤
```

### 4.3 学生 Portal

## 5. 交互与响应式

- 导航在 < 768px 收入抽屉，主 CTA 保留；
- 首页 Hero 在平板以下改为单列，图片在文案后；
- 卡片网格：桌面 3/4 列、平板 2 列、手机 1 列；
- Portal 在 < 1024px 将 Sidebar 变为 Sheet；
- 表格在手机端转为卡片，不做横向压缩；
- 所有点击目标至少 44×44px；
- 动画只用于 Hero 入场和 Route Card 状态推进，尊重 reduced motion。

## 6. 内容语气

- 具体、克制、可信，不使用“保录”“百分百过签”；
- CTA 使用动作：“获取免费评估”“查看可预约时间”；
- 错误给出解决方法：“该时段刚被预约，请选择其他时间”；
- 空状态指向下一步：“还没有申请项目，先确认选校清单”。

## 7. Figma 与 PRD 一致性更新清单

> 依据最新业务决策整理。现有 Figma 首版包含官网首页、导师团队、预约咨询和学生 Portal；以下项目需要在下一轮设计中更新。

### 7.1 现有画板修改

#### 01 官网首页

- 保留“获取免费评估”主 CTA；
- 将首次评估明确标注为“30 分钟线上背景评估”；
- 服务流程补充“账号激活”和“合同 + 服务确认单”两个节点；
- 会议平台文案统一为“腾讯会议或导师提供的其他会议链接”；
- 不出现 Google Calendar 或 Zoom 作为用户可见的必要条件。

#### 02 导师团队

- 将人员类型区分为“导师”和“顾问”：
  - 导师：负责留学定位、文书和申请服务流程；
  - 顾问：负责签证和其他事务型服务；
- 卡片增加角色标签与可服务的 CaseType；
- 筛选项增加“导师 / 顾问”，不再把所有人员统称为导师；
- 管理员是后台权限，不作为官网团队卡片的职业标签。

#### 03 预约咨询

- 主标题保持“首次背景评估 30 分钟”；
- 辅助说明增加“系统会为本次咨询预留最多 45 分钟”；
- 邮箱字段明确标注：
  - 必填；
  - 用于预约确认和账号激活；
- 成功页增加两个独立状态：
  - 预约已确认；
  - 激活邮件已发送，激活后可登录；
- 增加“会议开始前 12 小时可通过邮件链接取消或改期”；
- 学生不需要选择腾讯会议或手动链接，该选择由导师/系统处理；
- 会议链接未生成时显示“会议链接稍后发送”，不得阻塞预约成功。

#### 04 学生 Portal

- “我的方案”改为“签约与服务”，包含：
  - 通用合同条款 PDF；
  - 本次服务确认单；
  - 签字合同上传；
  - 付款凭证上传；
  - 管理员核验状态；
- 未完成签约与付款核验前，付费服务模块显示锁定原因；
- 服务激活后，只显示服务确认单购买的 Service Items；
- 保留“下一步行动 + 服务路线”的首页结构；
- 账号内不创建家长角色；合同详情单独显示实际签署人和付款人。

### 7.2 需要新增的画板

#### 05 签约与服务确认

```text
┌ 签约进度：表达兴趣 — 合同预览 — 答疑 — 上传签字合同 — 付款核验 ┐
│ 左：通用合同条款 PDF 预览                                     │
│ 右：本次服务确认单                                            │
│     服务项目 / 范围 / 原价 / 折扣 / 最终价格 / 有效期          │
│ [预约 60 分钟答疑] [下载合同] [上传签字合同]                   │
└───────────────────────────────────────────────────────────────┘
```

#### 06 预约成功与账号激活

- 预约状态、导师、时间和会议链接状态；
- “激活邮件已发送至 xxx@xxx.com”；
- 重新发送激活邮件；
- 取消/改期签名链接；
- 腾讯会议链接或“等待导师补充链接”状态。

#### 07 导师/顾问预约详情

- 学生背景摘要；
- AI 初评报告，仅服务人员可见；
- 报告编辑与“分享给学生”开关；
- 腾讯会议自动创建 / 手动会议链接切换；
- 咨询摘要、适配度、下一步和跟进日期。

#### 08 管理员服务与价格配置

- 套餐和单项服务；
- 服务范围与 Service Code；
- 基础价格、折扣和启停状态；
- 修改价格不影响历史服务确认单的提示；
- 通用合同模板版本管理。

### 7.3 原型交互

- “表达签约兴趣”解锁签约页面；
- “预约 60 分钟答疑”只在完成初评后可用；
- 上传签字合同和付款凭证后进入“等待管理员核验”；
- 管理员核验后，锁定模块转为对应服务入口；
- 取消预约同时更新平台预约状态，不把腾讯会议取消视为唯一成功条件。
